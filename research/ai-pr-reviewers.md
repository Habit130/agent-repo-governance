# AI pull-request reviewers: triggers, reporting and state

## Question

Which AI tools can review pull requests on a personal GitHub repository, and how does each get triggered, report findings and expose its state?

## Method and scope

- Sources are vendor documentation, vendor pricing pages, or vendor source code, accessed **2026-10-20**. Every quotation below is verbatim from the cited page.
- The ticket's required set is covered: the Claude Code GitHub Action, Anthropic-hosted Claude code review and security review, OpenAI Codex code review, Cursor Bugbot and GitHub Copilot code review. Gemini Code Assist, CodeRabbit and Qodo Review are added as other vendors whose primary documentation documents pull-request review.
- "Not documented in reviewed primary sources" means the fact was not found on the pages cited for that tool. It is not a claim that the capability is absent.
- Plan, quota and price statements are as published on the access date. No recommendation is made and no implication is drawn.

## Findings

### 1. Anthropic-hosted Claude Code Review (managed service)

- **What it is.** "With Code Review, Claude reviews the pull requests in your GitHub repositories." It runs "on Anthropic infrastructure, in a managed environment" and "Reviews don't run in self-hosted environments." It requires no workflow file in the repository. ([Code Review](https://code.claude.com/docs/en/code-review), [setup](https://code.claude.com/docs/en/code-review-setup))
- **Trigger.** Each repository has a **Review runs** setting with three values: "**Once after PR creation**: a review runs when a pull request is opened, reopened, or marked ready for review"; "**After every push**: a review runs on pushes to the pull request branch"; "**Manual (@claude review)**: opening or pushing to a pull request doesn't start a review." A top-level comment command `@claude review` starts one review; `@claude review always` also subscribes the PR to push-triggered reviews. Automatic reviews "skip" draft pull requests and pull requests from forks. ([setup](https://code.claude.com/docs/en/code-review-setup), [reading reviews](https://code.claude.com/docs/en/code-review-pull-requests))
- **Repository files.** `REVIEW.md` at the repository root (and optionally in subdirectories) carries review-only instructions; `CLAUDE.md` files carry project-wide rules. "Code Review reads `REVIEW.md` from the pull request's base branch or from the default branch, never from the pull request's own changes." Subdirectory `REVIEW.md` files are read only under branch-protection conditions that the docs enumerate. ([customize](https://code.claude.com/docs/en/code-review-customize))
- **Output.** "Findings: inline comments on the lines concerned, with a summary in the review body" and "A check run: named **Claude Code Review**, with the findings listed in its details." The check-run details table is sorted by severity. "A review never approves or blocks the pull request." ([Code Review](https://code.claude.com/docs/en/code-review), [reading reviews](https://code.claude.com/docs/en/code-review-pull-requests))
- **Severity vocabulary.** Three levels: "🔴 Important — A bug that should be fixed before merging"; "🟡 Nit — A minor issue, worth fixing but not blocking"; "🟣 Pre-existing — A bug that exists in the codebase but wasn't introduced by this PR." ([reading reviews](https://code.claude.com/docs/en/code-review-pull-requests))
- **Required status check.** The service publishes a check run named `Claude Code Review`. The docs state: "The check run concludes as neutral, or as skipped when an automatic review didn't run because a push changed no files. It never concludes as a failure, so a finished review doesn't fail a required check." GitHub branch protection accepts checks or commit statuses and requires a `successful`, `skipped` or `neutral` result, so the check can be required but its documented conclusions never block. ([reading reviews](https://code.claude.com/docs/en/code-review-pull-requests), [GitHub protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches))
- **Account, plan and price.** Availability: "**Plans**: Team and Enterprise"; "**Code hosts**: repositories hosted on GitHub"; "Code Review isn't available to organizations with Zero Data Retention enabled or with the HIPAA configuration applied." Setup requires a Claude organization Owner and a GitHub organization Owner to install the app. Billing: "Code Review has no flat per-review price"; it is "billed on token usage through usage credits, separately from your plan's included usage" and "billed to your organization, not to the developer who opened the PR." ([Code Review](https://code.claude.com/docs/en/code-review), [setup](https://code.claude.com/docs/en/code-review-setup), [costs](https://code.claude.com/docs/en/code-review-costs))
- **Credentials and installation.** "Install the Claude GitHub App"; the app "holds a broader permission set that other Claude features share." No workflow file and no repository secret are documented for this service. ([setup](https://code.claude.com/docs/en/code-review-setup), [Code Review](https://code.claude.com/docs/en/code-review))
- **New commits.** With **After every push**, "a review runs on pushes to the pull request branch, catching new issues as the pull request evolves and auto-resolving threads when you fix flagged issues." A later automatic review "focuses on what changed since the last review and posts fewer nits and pre-existing findings." With **Once after PR creation**, pushes do not start a review unless the PR was subscribed with `@claude review always`. ([setup](https://code.claude.com/docs/en/code-review-setup), [reading reviews](https://code.claude.com/docs/en/code-review-pull-requests))

### 2. Claude Code GitHub Action (`anthropics/claude-code-action`)

- **What it is.** "A general-purpose Claude Code action for GitHub PRs and issues that can answer questions and implement code changes." It "runs Claude Code inside your repository's workflows." ([README](https://github.com/anthropics/claude-code-action/blob/main/README.md), [GitHub Actions docs](https://code.claude.com/docs/en/github-actions))
- **Trigger.** Interactive mode waits for "the trigger phrase, `@claude` by default, in an issue or pull request comment, in a pull request review, or in the body or title of a newly opened issue." Automation mode runs when "the workflow provides a `prompt` input" and is "subject only to the checks on who can trigger runs." The review example uses `on: pull_request: types: [opened, synchronize]`. ([GitHub Actions docs](https://code.claude.com/docs/en/github-actions), [solutions](https://github.com/anthropics/claude-code-action/blob/main/docs/solutions.md))
- **Repository files.** `CLAUDE.md` supplies project standards; the docs advise "Create a `CLAUDE.md` file in your repository root to define code style guidelines, review criteria, project-specific rules, and preferred patterns." Review behavior is otherwise carried by the workflow YAML and the `prompt` input. `REVIEW.md` is not documented for this action. ([GitHub Actions docs](https://code.claude.com/docs/en/github-actions), [usage](https://github.com/anthropics/claude-code-action/blob/main/docs/usage.md))
- **Output.** The action can post to the issue or pull request when the prompt directs it to and it has a tool that can post; inline review comments go through the `mcp__github_inline_comment__create_inline_comment` tool. In automation mode, "By default, results appear in the workflow run log rather than a comment"; the documented review workflow passes `--comment` so Claude "posts its review on the pull request, as an inline comment on each issue it finds or as one summary comment when it finds none." `track_progress: true` adds a tracking comment; `structured_output` exposes validated JSON as an action output. ([solutions](https://github.com/anthropics/claude-code-action/blob/main/docs/solutions.md), [GitHub Actions docs](https://code.claude.com/docs/en/github-actions), [usage](https://github.com/anthropics/claude-code-action/blob/main/docs/usage.md))
- **Severity vocabulary.** No built-in severity scale is documented. Severity is whatever the `prompt` requests; the security example instructs: "Rate severity as: CRITICAL, HIGH, MEDIUM, LOW, or NONE." ([solutions](https://github.com/anthropics/claude-code-action/blob/main/docs/solutions.md))
- **Required status check.** The action runs as a GitHub Actions job, and GitHub branch protection can require checks or commit statuses. The action documentation does not describe a built-in failure on findings or a review verdict; a workflow would need its own failing step to turn findings into a failed check. ([GitHub Actions docs](https://code.claude.com/docs/en/github-actions), [GitHub protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches))
- **Account, plan and price.** Requires admin access to the repository for setup. Authentication is a Claude API key, a Claude subscription OAuth token "available on Pro, Max, Team, and Enterprise plans", or Amazon Bedrock, Google Cloud's Agent Platform or Microsoft Foundry credentials. Each run consumes "GitHub Actions minutes" and "API tokens"; with an OAuth token, "runs use your Claude subscription instead of API billing." ([GitHub Actions docs](https://code.claude.com/docs/en/github-actions), [README](https://github.com/anthropics/claude-code-action/blob/main/README.md))
- **Credentials and installation.** Quick setup runs `/install-github-app`, installs the Claude GitHub App, saves `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` as a repository secret, and opens a workflow PR. Manual setup requires installing the app and adding the secret. The app requests Contents (read/write), Issues (read/write), Pull requests (read/write), Checks (read/write) and other permissions listed in the docs. ([GitHub Actions docs](https://code.claude.com/docs/en/github-actions))
- **New commits.** The workflow's event filter decides. The documented automatic review example uses "`opened` and `synchronize` (new commits)" and states under key configuration: "Triggers on `opened` and `synchronize` (new commits)." Each run is a fresh action invocation; no incremental-review state is documented. ([solutions](https://github.com/anthropics/claude-code-action/blob/main/docs/solutions.md))

### 3. Claude Code Security Reviewer (`anthropics/claude-code-security-review`, GitHub Action)

- **What it is.** "An AI-powered security review GitHub Action using Claude to analyze code changes for security vulnerabilities." It is "diff-aware": "For PRs, only analyzes changed files." ([README](https://github.com/anthropics/claude-code-security-review/blob/main/README.md))
- **Trigger.** The documented workflow is `on: pull_request`; the action runs as a workflow step. Its `run-every-commit` input controls whether the cache is skipped: default `false`, described as "Run ClaudeCode on every commit (skips cache check). Warning: May increase false positives on PRs with many commits." ([README](https://github.com/anthropics/claude-code-security-review/blob/main/README.md))
- **Repository files.** Configuration is through action inputs, not a review-instruction file: `claude-api-key`, `comment-pr`, `upload-results`, `exclude-directories`, `claude-model`, `claudecode-timeout`, `run-every-commit`, `false-positive-filtering-instructions` and `custom-security-scan-instructions`. The last two take "Path to custom ... instructions text file". `AGENTS.md`, `CLAUDE.md` and `REVIEW.md` are not named in the README. ([README](https://github.com/anthropics/claude-code-security-review/blob/main/README.md))
- **Output.** "PR Comments: Automatically comments on PRs with security findings"; "Findings are posted as review comments on the specific lines of code." It uploads a results JSON artifact by default and exposes `findings-count` and `results-file` outputs. ([README](https://github.com/anthropics/claude-code-security-review/blob/main/README.md))
- **Severity vocabulary.** The audit prompt requires `"severity": "HIGH"` in its JSON schema and defines: "**HIGH**: Directly exploitable vulnerabilities leading to RCE, data breach, or authentication bypass"; "**MEDIUM**: Vulnerabilities requiring specific conditions but with significant impact"; "**LOW**: Defense-in-depth issues or lower-impact vulnerabilities." It also instructs: "Focus on HIGH and MEDIUM findings only." ([prompts.py](https://github.com/anthropics/claude-code-security-review/blob/main/claudecode/prompts.py))
- **Required status check.** The action is a workflow job, so its job check can be required like any GitHub Actions check. No built-in fail-on-findings behavior is documented; the action exposes `findings-count`, but the README does not describe a failing step or gate. ([README](https://github.com/anthropics/claude-code-security-review/blob/main/README.md), [GitHub protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches))
- **Account, plan and price.** Needs a `claude-api-key` that "needs to be enabled for both the Claude API and Claude Code usage"; GitHub Actions minutes; the default model is `claude-opus-4-1-20250805`. No subscription-plan requirement is stated. ([README](https://github.com/anthropics/claude-code-security-review/blob/main/README.md))
- **Credentials and installation.** Add `.github/workflows/security.yml` with `permissions: pull-requests: write` and `contents: read`, then pass `claude-api-key: ${{ secrets.CLAUDE_API_KEY }}`. The README states the action "is not hardened against prompt injection attacks and should only be used to review trusted PRs." ([README](https://github.com/anthropics/claude-code-security-review/blob/main/README.md))
- **New commits.** The documented workflow is `on: pull_request`; the action README does not enumerate the pull-request activity types it responds to. It documents a cache check, and `run-every-commit: true` skips it. The README's warning says this "May increase false positives on PRs with many commits." ([README](https://github.com/anthropics/claude-code-security-review/blob/main/README.md))

### 4. OpenAI Codex code review

- **Trigger.** Comment `@codex review` on a pull request; "Wait for Codex to react (👀) and post a review." Automatic reviews are enabled with "**Automatic review** under **Personal preferences**" and "Choose when reviews run with **Review trigger**." A one-off focus can be added: "`@codex review for issues in the database migration`." ([Codex GitHub docs](https://learn.chatgpt.com/docs/third-party/github))
- **Repository files.** "Codex searches your repository for `AGENTS.md` files and follows the applicable code review rules. Add a `## Code Review Rules` section to the file closest to the code the rules govern." Repository-wide rules go in the root `AGENTS.md`; service-specific rules go in a nested file such as `services/experiment_reporting/AGENTS.md`. ([Codex GitHub docs](https://learn.chatgpt.com/docs/third-party/github))
- **Output.** "Codex posts a review on the pull request, just like a teammate would." "In GitHub, Codex flags only P0 and P1 issues so review comments stay focused on high-priority risks." The docs describe a standard GitHub code review; no check run is documented. ([Codex GitHub docs](https://learn.chatgpt.com/docs/third-party/github))
- **Severity vocabulary.** P0 and P1 only: "Codex flags only P0 and P1 issues." The review docs do not define P0/P1 in more detail. ([Codex GitHub docs](https://learn.chatgpt.com/docs/third-party/github))
- **Required status check.** Not documented. The review is described as a GitHub review; no check run, commit status or branch-protection behavior appears in the Code Review documentation. ([Codex GitHub docs](https://learn.chatgpt.com/docs/third-party/github))
- **Account, plan and price.** The plan matrix marks "GitHub code review and automatic PR reviews" as available on Plus, Pro, Business and Enterprise, and unavailable with an API key. The Plus plan ($20/month) lists "Cloud-based integrations like automatic code review"; the API-key plan says "No cloud-based features (GitHub code review, Slack, etc.)". "Code Review usage applies only when Codex runs reviews through GitHub" and counts toward the plan's usage. ([Codex pricing](https://learn.chatgpt.com/docs/pricing))
- **Credentials and installation.** "Connect your GitHub repository to Codex"; "Go to Codex settings ... Choose your repository, then turn on Automatic review." Setup needs "GitHub push or admin permission for its settings." The Code Review docs refer to "the ChatGPT Codex connector" and "required repository permissions" without listing the app's permission set. ([Codex GitHub docs](https://learn.chatgpt.com/docs/third-party/github), [Code review](https://learn.chatgpt.com/docs/code-review))
- **New commits.** Automatic review has a **Review trigger** setting, but the Code Review page does not enumerate its options. The separate Security Review page documents triggers "**On PR open**", "**On every push**" and "**Whenever code review runs**". The Code Review page says automatic review applies "to repositories with code review enabled" and can run without a comment. ([Codex GitHub docs](https://learn.chatgpt.com/docs/third-party/github), [Security Review](https://learn.chatgpt.com/docs/security/security-review))

### 5. OpenAI Codex Security Review

- **Trigger.** Turn on "**Auto security review**" under "**Review security vulnerabilities**"; "Set **Trigger** to **Whenever code review runs** to run it alongside Code Review." Manual: "`@codex security review`". ([Security Review](https://learn.chatgpt.com/docs/security/security-review))
- **Repository files.** "Add threat-model context": use an existing Codex Security scan configuration or "provide the path to a threat model file checked into the repository." "If you do not specify a source, Codex regenerates the threat model for every review." Reporting thresholds can be changed globally or with "path-based overrides." `AGENTS.md` is not named on this page. ([Security Review](https://learn.chatgpt.com/docs/security/security-review))
- **Output.** "Codex reacts while the review is running, then posts security findings directly on the pull request. Open the associated Codex task and select the **Security Report** tab to view the full report." If no issues meet the threshold, "Codex does not post findings to the pull request." ([Security Review](https://learn.chatgpt.com/docs/security/security-review))
- **Severity vocabulary.** "By default, automatic Codex Security Reviews report **High** and **Critical** findings, while manually requested reviews report **Medium**, **High**, and **Critical** findings." Thresholds are configurable. ([Security Review](https://learn.chatgpt.com/docs/security/security-review))
- **Required status check.** Not documented; no check run or commit status is described. ([Security Review](https://learn.chatgpt.com/docs/security/security-review))
- **Account, plan and price.** "Codex Security Review is available to ChatGPT Enterprise, Business, Edu, and Pro customers. It isn't available on Plus. Security reviews consume included Codex allowance or ChatGPT credits." ([Security Review](https://learn.chatgpt.com/docs/security/security-review), [Codex pricing](https://learn.chatgpt.com/docs/pricing))
- **Credentials and installation.** Requires "Codex Security Review access for your workspace", "Codex cloud ... set up with a connected GitHub repository", and "GitHub push or admin permission for the repository settings." ([Security Review](https://learn.chatgpt.com/docs/security/security-review))
- **New commits.** Trigger options are "**On PR open** runs independently when a pull request is opened"; "**On every push** runs independently after new commits are pushed"; "**Whenever code review runs** requires Code Review and runs Codex Security Review alongside it." "Later pushes can trigger another review according to **Trigger**." ([Security Review](https://learn.chatgpt.com/docs/security/security-review))

### 6. Cursor Bugbot

- **Trigger.** "Bugbot runs automatically when a PR is created or updated. To trigger a review manually, comment `cursor review` or `bugbot run` on any PR." Settings can make it "Run **only when mentioned**" or "Run **only once** per PR, skipping subsequent commits." Enterprise teams can trigger reviews through `POST /bugbot/review`. ([Bugbot help](https://cursor.com/help/ai-features/bugbot), [Bugbot reference](https://cursor.com/docs/bugbot))
- **Repository files.** "Create `.cursor/BUGBOT.md` files in your repository to give Bugbot project-specific review guidelines. Bugbot always includes the root file and traverses upward from changed files to find relevant context." Optional `.cursor/config/bugbot.yaml` configures triggers, effort, incremental review and PR summary; Bugbot "reads `.cursor/config/bugbot.yaml` at the repo root from the PR's base branch." "Cursor project rules (`*.mdc` files in `.cursor/rules/`) do not apply to Bugbot runs." ([Bugbot help](https://cursor.com/help/ai-features/bugbot), [Bugbot reference](https://cursor.com/docs/bugbot))
- **Output.** "It analyzes every pull request for bugs, security vulnerabilities, and code quality issues, leaving inline comments with explanations and suggested fixes." It also writes a PR summary, by default into the PR description, and "publishes a status for each review run. On GitHub, this appears as a check named `Cursor Bugbot`." ([Bugbot help](https://cursor.com/help/ai-features/bugbot), [Bugbot reference](https://cursor.com/docs/bugbot))
- **Severity vocabulary.** No complete severity ladder is published. The public API's per-finding object includes a `severity` field, with examples `"high"` and `"medium"`; custom rules can create "a blocking Bug" or "a non-blocking Bug." ([Bugbot reference](https://cursor.com/docs/bugbot))
- **Required status check.** The check is explicitly documented: "If you use branch protection, require the Bugbot check or build status to make sure Bugbot runs before merge." Conclusions are `success`, `neutral` and `failure`: "`neutral`: Bugbot found issues, the run was cancelled by a newer commit, or Bugbot hit an internal error. This is the default conclusion when Bugbot reports findings." "Requiring the status alone does not block merges on findings because findings default to `neutral`"; an organization with fail-on-unresolved-issues can "make unresolved findings produce a failing status." Bugbot "does not emit a `skipped` conclusion." ([Bugbot reference](https://cursor.com/docs/bugbot))
- **Account, plan and price.** "Bugbot uses usage-based billing." "Some Teams and Individual plans include monthly Bugbot usage. You can enable usage-based billing for reviews on all PRs." Billing first consumes included usage, then "bills additional reviews from your prepaid credit, or from on-demand spend on a legacy Cursor plan." Pricing "changed with the May 2026 pricing update"; current rates are on the pricing page. ([Bugbot help](https://cursor.com/help/ai-features/bugbot), [Bugbot reference](https://cursor.com/docs/bugbot))
- **Credentials and installation.** "Connect your repositories through the Cursor dashboard"; on GitHub, "connecting turns Bugbot on for the repositories you grant access to." No API key is required for the standard integration; Enterprise teams can create an API key for the Bugbot API. ([Bugbot help](https://cursor.com/help/ai-features/bugbot), [Bugbot reference](https://cursor.com/docs/bugbot))
- **New commits.** "Bugbot runs automatically when a PR is created or updated"; the reference says "Runs **automatic reviews** on every PR update." "By default, Bugbot reviews only the changes since the previous Bugbot review"; "Turn off **Incremental Review** ... to review the full pull request diff on every push." The status is `neutral` when "the run was cancelled by a newer commit"; "Run **only once** per PR" is an available setting. ([Bugbot help](https://cursor.com/help/ai-features/bugbot), [Bugbot reference](https://cursor.com/docs/bugbot))

### 7. GitHub Copilot code review

- **Trigger.** Request a review under "Reviewers" next to Copilot; request through the REST API by adding `copilot-pull-request-reviewer[bot]` as a reviewer. Automatic reviews come from "your user settings, repository rulesets, or organization rulesets"; a user can enable "**Automatic Copilot code review**" and optionally "**Review new pushes**" and "**Review draft pull requests**." ([Copilot how-to](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review), [configure](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/configure-code-review))
- **Repository files.** Copilot supports `.github/copilot-instructions.md`, path-specific `.github/instructions/**/*.instructions.md`, repository-root `AGENTS.md` and organization instructions; skills live under `.github/skills`. Review environment is customized with `.github/workflows/copilot-setup-steps.yml` or `.github/workflows/copilot-code-review.yml`; if the latter exists, it "is used for Copilot code review instead of `copilot-setup-steps.yml`." ([custom instructions](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review), [how-to](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review))
- **Output.** Copilot "leaves a 'Comment' review, not an 'Approve' review or a 'Request changes' review" by default, and labels "each comment with a severity level of 'High,' 'Medium,' or 'Low'." It provides suggested changes and an overview comment with an approval assessment. No check run is documented. ([Copilot how-to](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review))
- **Severity vocabulary.** High, Medium, Low: "Copilot labels each comment with a severity level of 'High,' 'Medium,' or 'Low'." ([Copilot how-to](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review))
- **Required status check.** No check run or commit status is documented. By default, "Copilot leaves a 'Comment' review ... This means that, by default, Copilot's reviews do not count toward required approvals for the pull request." With approvals enabled, Copilot "can submit an approving review that satisfies your repository's required-approval rule"; this is an approval, not a status check. ([Copilot how-to](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review))
- **Account, plan and price.** Copilot code review is not available on Copilot Free. Automatic review is "available on the Copilot Pro, Copilot Pro+, and Copilot Max plans, and with a Copilot Business or Copilot Enterprise license." Each review consumes AI credits: a review "typically consumes an estimated $0.05 USD to $1 USD worth of AI credits with 'Lite' effort, and $0.25 USD to $5 USD worth of AI credits with 'Balanced' effort," plus GitHub Actions minutes. ([configure](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/configure-code-review), [concept](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review))
- **Credentials and installation.** Built into GitHub; no app installation is documented. A Copilot license is required for individual use, and agentic capabilities use GitHub Actions runners; "You do not need to have GitHub Actions enabled in your organization or enterprise to use the agentic capabilities in code review." ([concept](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review))
- **New commits.** "Unless Copilot has been configured to review each push to a pull request, it will only review a pull request once." "Review new pushes" must be enabled in user settings or a ruleset; otherwise re-review is manual through the re-request button. If Copilot approved and new commits are pushed, "the approval is dismissed, and you can re-request a review." ([concept](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review), [how-to](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review))

### 8. Gemini Code Assist for GitHub

- **Trigger.** "When you open the new pull request, Gemini Code Assist provides an initial review." Manual commands: "`/gemini summary` — Posts a summary of the changes in the pull request"; "`/gemini review` — Posts a code review of the changes in the pull request"; "`/gemini` — Manually invokes Gemini Code Assist in comments"; "`/gemini help` — Overview of the available commands." The `.gemini/config.yaml` `pull_request_opened` block gates the initial behavior ("Posts a code review on pull request open. Default: true"). No label trigger is documented. ([use](https://docs.cloud.google.com/gemini/docs/code-review/use-code-assist-github), [customize](https://docs.cloud.google.com/gemini/docs/code-review/customize-repo-review))
- **Repository files.** `.gemini/config.yaml` in the repository root; `.gemini/styleguide.md` for a natural-language style guide. The published schema covers `have_fun`, `ignore_patterns`, `memory_config`, `code_review` (`disable`, `comment_severity_threshold`, `max_review_comments`) and `pull_request_opened`. `AGENTS.md` and `GEMINI.md` are not documented for this integration. ([customize](https://docs.cloud.google.com/gemini/docs/code-review/customize-repo-review), [style guide](https://docs.cloud.google.com/gemini/docs/code-review/style-guide))
- **Output.** "`gemini-code-assist[bot]` is automatically added as a reviewer to the pull request. Gemini Code Assist adds an issue comment in the **Conversation** tab of the pull request with its feedback and proceeds to add comments about modified portions of the code." Comments include "Code suggestion that can be committed directly from GitHub." No check run, commit status or approve/request-changes review event is documented. ([use](https://docs.cloud.google.com/gemini/docs/code-review/use-code-assist-github))
- **Severity vocabulary.** "Severity of the issue, given as Critical, High, Medium, and Low." The config enum is `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`; `comment_severity_threshold` defaults to `MEDIUM`. Review focus areas, separate from severity, are "Correctness ... Efficiency ... Maintainability ... Security ... Miscellaneous." ([use](https://docs.cloud.google.com/gemini/docs/code-review/use-code-assist-github), [customize](https://docs.cloud.google.com/gemini/docs/code-review/customize-repo-review), [style guide](https://docs.cloud.google.com/gemini/docs/code-review/style-guide))
- **Required status check.** Not documented. The reviewed pages describe only an issue comment, inline comments and the bot as reviewer; no check run, commit status or required-check behavior is stated. ([use](https://docs.cloud.google.com/gemini/docs/code-review/use-code-assist-github))

### 9. CodeRabbit

- **Trigger.** Automatic review is the default: "By default, `enabled` is `true` and CodeRabbit reviews every eligible PR automatically"; draft PRs are skipped unless `drafts: true`; `base_branches` defaults to the repository's default branch. Manual: "you can always trigger a review manually by commenting `@coderabbitai review` (incremental) or `@coderabbitai full review` (from scratch)." Positive label matches can trigger reviews when `enabled: false`. "For public repositories with less than 10 stars, CodeRabbit requires reviews to be triggered manually." ([auto-review](https://docs.coderabbit.ai/configuration/auto-review), [plans](https://docs.coderabbit.ai/management/plans))
- **Repository files.** `.coderabbit.yaml` (or `.coderabbit.config.ts`) at the repository root; a committed `.coderabbit.yaml` takes precedence over the TypeScript file. CodeRabbit "automatically detects coding guideline files such as .cursorrules, CLAUDE.md, and AGENTS.md"; the documented default pattern list includes `**/AGENTS.md`, `**/CLAUDE.md`, `**/.claude/rules/**/*.md`, `.github/copilot-instructions.md`, `**/GEMINI.md` and others. `REVIEW.md` is not documented in the reviewed CodeRabbit sources. ([YAML configuration](https://docs.coderabbit.ai/getting-started/yaml-configuration), [code guidelines](https://docs.coderabbit.ai/knowledge-base/code-guidelines))
- **Output.** A "walkthrough comment" at the top of the PR comment thread, a plain-language summary written into the PR description, and inline code comments. CodeRabbit publishes "the `CodeRabbit` check run that reports review status"; `reviews.commit_status` can "Mirror review progress using legacy commit statuses for compatibility with required checks." CodeRabbit can "request changes" or approve through its request-changes workflow. ([walkthroughs](https://docs.coderabbit.ai/pr-reviews/walkthroughs), [GitHub integration](https://docs.coderabbit.ai/platforms/github-com), [configuration reference](https://docs.coderabbit.ai/reference/configuration), [request-changes workflow](https://docs.coderabbit.ai/pr-reviews/request-changes-workflow))
- **Severity vocabulary.** The review vocabulary is "🔴 Critical", "🟠 Major", "🟡 Minor", "🔵 Trivial" and "⚪ Info". Categories include "Security & Privacy", "Stability & Availability", "Data Integrity & Integration", "Functional Correctness", "Performance & Scalability" and "Maintainability & Code Quality." The Change Stack findings page describes four independent label axes (type, severity, category, effort) and the same four ranked severities plus `info` and `none`. ([code review overview](https://docs.coderabbit.ai/guides/code-review-overview), [findings](https://docs.coderabbit.ai/change-stack/findings))
- **Required status check.** A `CodeRabbit` check run exists, and `reviews.commit_status` can mirror review progress to commit statuses for required checks. The only check explicitly documented as requireable by branch protection is the separate **CodeRabbit Security** check: "To block merging, a GitHub repository administrator must configure a ruleset ... that requires **CodeRabbit Security**." Requiring the general `CodeRabbit` review check by name is not documented in the reviewed sources. ([GitHub integration](https://docs.coderabbit.ai/platforms/github-com), [configuration reference](https://docs.coderabbit.ai/reference/configuration), [security check](https://docs.coderabbit.ai/security/pull-request-check))
- **Account, plan and price.** The Free plan has "Unlimited public and private repositories" but "PR summarization only; code reviews are available through the VS Code extension and CLI." Open-source projects "receive Team features with no paid subscription required." Paid plans: Essentials "$24 per developer per month billed annually, or $30 month-to-month"; Team "$48 ... or $60"; Advanced "$72 ... or $90"; Enterprise is contact-sales. New organizations start with a "14-day Advanced trial." The GitHub integration supports personal repositories: "For personal repositories, select your account name." ([plans](https://docs.coderabbit.ai/management/plans), [GitHub](https://docs.coderabbit.ai/platforms/github-com))
- **Credentials and installation.** A GitHub account with "owner-level permissions" for at least one repository; install is a GitHub App authorization ("Install & Authorize"). Permissions include read/write to "Checks, code, commit statuses, issues, and pull requests"; "CodeRabbit needs read-and-write access to checks so that it can publish the `CodeRabbit` check run." No API key is documented for PR reviews. ([GitHub](https://docs.coderabbit.ai/platforms/github-com))
- **New commits.** "CodeRabbit re-reviews a PR after each new push, focusing on the **commits added since the last review**." `auto_incremental_review` defaults to `true`; `auto_pause_after_reviewed_commits` defaults to `5`, and automatic incremental reviews pause after that many reviewed commits. `@coderabbitai pause` and `@coderabbitai resume` control automatic reviews. ([auto-review](https://docs.coderabbit.ai/configuration/auto-review))

### 10. Qodo Review (formerly Qodo Merge / PR-Agent)

- **Trigger.** "Automatic is the default. Qodo runs a review as soon as a pull request is opened, reopened, or marked ready for review, without any manual trigger." Manual: comment "`/agentic_review`". The portal's **Code review trigger** options are "**Manual only**", "**Published PRs** (default)" and "**Draft and published PRs**." Labels are used to skip reviews, not to start them: "Pull requests carrying any of the listed labels are not reviewed." ([trigger](https://docs.qodo.ai/code-review/use-qodo-in-prs), [workflow](https://docs.qodo.ai/configuration/workflow))
- **Repository files.** `.pr_agent.toml` at the root of the default branch; `REVIEW.md` "committed at the root of a repository" for project-specific review guidelines; Qodo can "Import from AGENTS.md, CLAUDE.md, and other supported files." Organization-wide settings can live in a repository named `pr-agent-settings`. ([config file](https://docs.qodo.ai/configuration/configuration-file), [REVIEW.md](https://docs.qodo.ai/governance/use-review-md), [governance](https://docs.qodo.ai/governance/governance-management))
- **Output.** The default is "`both` – a summary comment is posted and findings are also added inline"; the portal labels this "Summary & Inline (default)." Findings can include one-click "Apply Suggestion" fixes and agent prompts. Qodo can add itself as a reviewer through its self-review setting. No check run or commit status is documented as review output. ([reference](https://docs.qodo.ai/configuration/configuration-and-command-reference), [display](https://docs.qodo.ai/configuration/display), [self-review](https://docs.qodo.ai/code-review/self-review))
- **Severity vocabulary.** "**High**: High-priority or blocking issues"; "**Medium**: Non-blocking issues"; "**Low**: Lower-impact or informational findings." Categories: "Bugs", "Rule violations", "Requirement gaps", "Cross-repo conflicts", "Skill insights"; quality-impact labels: "Correctness", "Security", "Reliability", "Performance", "Observability." Terminology is configurable, with documented presets including "High, Medium, Low (default)", "Critical, Warning, Informational", "Required, Recommended, Optional" and "P0, P1, P2". ([anatomy](https://docs.qodo.ai/code-review/comment-anatomy), [display](https://docs.qodo.ai/configuration/display))
- **Required status check.** Not documented in the reviewed primary sources. The docs describe comments, inline findings and reviewer assignment; no check run, commit status or branch-protection behavior is stated. The installation permissions include "Checks: Read & Write (if check run annotations are enabled)." ([anatomy](https://docs.qodo.ai/code-review/comment-anatomy), [troubleshooting](https://docs.qodo.ai/code-review/troubleshooting))
- **Account, plan and price.** Every workspace starts with "a 14-day free trial"; billing "is usage-based (not seat-based)" with a shared workspace credit pool. The vendor pricing page lists "Pro Team" with `$.012/credit`, tiers of 2,500 credits ("~18 Reviews/Mo"), 5,000 credits ("~36 Reviews/Mo") and 20,000 credits ("~144 Reviews/Mo"), and Enterprise as "Custom plan For 30+ users." The open-source program offers free code review for public repositories with "200+ GitHub stars." The install prerequisite is "GitHub organization admin access"; a personal non-organization account is not documented. ([pricing docs](https://docs.qodo.ai/pricing-and-usage), [pricing page](https://www.qodo.ai/pricing/), [OSS](https://docs.qodo.ai/open-source-program), [install](https://docs.qodo.ai/install-qodo/github/qodo-multi-tenant))
- **Credentials and installation.** A Qodo portal workspace and GitHub organization admin access; the wizard redirects to GitHub to "Authorize the installation and confirm repository access." Documented permissions include "Pull requests: Read & Write", "Issues: Read & Write", "Contents: Read" and "Checks: Read & Write (if check run annotations are enabled)." ([install](https://docs.qodo.ai/install-qodo/github/qodo-multi-tenant), [troubleshooting](https://docs.qodo.ai/code-review/troubleshooting))
- **New commits.** The portal documents "**Review every push**: Re-runs the code review and updates the existing review comment on every new commit pushed to the pull request" with "Enable (default) / Disable." In `.pr_agent.toml`, `handle_push_trigger` is documented with default `false`, and `review_agent.enable_incremental_review` defaults to `true`, so follow-up reviews "focus only on changes since the last review." ([workflow](https://docs.qodo.ai/configuration/workflow), [persistent comments](https://docs.qodo.ai/code-review/persistent-review-comments))

## Open gaps

- **Claude Code Review personal-account eligibility.** The docs state Team and Enterprise plans, and setup lists a Claude organization Owner and a GitHub organization Owner. They do not state whether an individual on a Team/Enterprise plan can add a repository owned by a personal GitHub account.
- **Claude Code Action and Security Reviewer failure semantics.** Both run as GitHub Actions jobs and can therefore be required checks, but neither documents a built-in fail-on-findings step. The Security Reviewer exposes `findings-count`; the Claude Code Action does not document a review verdict or severity gate.
- **Codex review-trigger options.** The Code Review page documents a **Review trigger** setting but does not enumerate its values. The Security Review page enumerates `On PR open`, `On every push` and `Whenever code review runs`; whether Code Review has the same set is not stated.
- **Codex check state.** No check run, commit status or branch-protection behavior is documented for Codex code review or Security Review. The docs describe a GitHub review and PR comments only.
- **Bugbot severity ladder and current rates.** The API examples show `high` and `medium`; no complete severity vocabulary is published. Current per-review rates are on the pricing page, not in the docs.
- **Copilot credit allowance and check state.** The docs give estimated per-review AI-credit ranges but not the included monthly allowance for each plan. No check run or required-status behavior is documented; approvals are a separate mechanism.
- **Gemini update behavior and product status.** The reviewed pages do not document whether a push triggers another review. The same pages describe a Preview with no charges, while the consumer-version deprecation page says consumer installations end on 2026-07-17 and the enterprise version is separate; new Standard/Enterprise subscriptions could not be purchased after 2026-10-09.
- **CodeRabbit `REVIEW.md` and general check requiring.** `REVIEW.md` does not appear in the reviewed CodeRabbit sources. A general `CodeRabbit` check run exists, but only the separate `CodeRabbit Security` check is explicitly documented as requireable.
- **Qodo push default and personal accounts.** The portal documents **Review every push** as enabled by default, while the `.pr_agent.toml` reference lists `handle_push_trigger` with default `false`. The install guide requires GitHub organization admin access; personal-account installation is not documented.
- **Time-bound plan and price statements.** Prices, plan names, quotas and deprecation dates above are as published on 2026-10-20; vendor pages change without notice.
