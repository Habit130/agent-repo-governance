# A pure revert takes the low path, sensitive paths included

A PR that exactly undoes one merged squash commit takes the low path even on a sensitive path when the governance gate confirms it, so an emergency revert does not wait for a Reviewer session. The original rationale was returning to a state that already passed review; a commit from before governance does not support that rationale.

From version 4, confirmation also requires the governance record to exist in the reverted commit's parent. The commit must still be on the default branch with one parent, and its revert recomputed on the PR's merge-base must equal the head's tree. A revert of a commit from before governance, including the commit that first added the record, is unconfirmed and tiered as usual. Reverting a one-way door remains an escalation.

Version 4's gate uses git objects alone rather than a GitHub lookup proving that the commit was a merged PR's squash commit: an API fault must not become another reason the required check fails. Its accepted boundary is that a qualifying commit pushed without a PR after governance began can still confirm; Merge watch records that push as a miss.

From version 5, the gate also confirms by a GitHub read that the named commit is the squash commit of a PR merged into the default branch, the same merged-PR test Merge watch uses. Two independent reviews of version 4 Initialize PRs each raised that boundary as Important, since the policy defines a pure revert as undoing a merged squash commit and nothing proved it. The read runs only after the git conditions hold, so other PRs make no new call. Version 4's reason still governs it: when GitHub shows no such PR or can't be read, the revert is unconfirmed and the floors judge it, and that alone never fails the gate. habit rejected keeping version 4's boundary and narrowing the policy's wording to what the gate proved. Confirmation is still not proof that review occurred.

Each gate rule takes effect when a repository adopts its version. During the version 4 planning round, habit instructed repositories still on earlier versions to tier a pre-governance revert as usual. Version 5 was still a draft when habit approved the GitHub read on 2026-11-19. Releasing a version and upgrading each repository are separate decisions ([ADR 0029](0029-changes-accumulate-in-one-draft-version.md)).
