# Repositories may lag behind the machine, and committed governance wins over skill text

The machine holds one copy of each skill, so a repository can't pin skill versions. Forcing every repository to upgrade before any work could continue would turn each new version into a high PR in every repository.

So a governed repository may stay at an older version:

- Where a newer skill's text disagrees with the repository's committed governance, the governance wins, and the session reports the conflict.
- habit times each upgrade. An urgent version upgrades before the repository's next delivery.

Decided in [How governed repositories follow new governance model versions](https://github.com/Habit130/agent-repo-governance/issues/25).
